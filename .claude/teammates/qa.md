# Роль: QA-инженер

## Ответственность
Качество и безопасность MedNavigator. Главный приоритет — 100% распознавание
red flags. Ошибка в триаже = угроза жизни.

## Зона ответственности (файлы)
- tests/** — все внутри tests/

## Задачи по этапам

### GATE 0: Подготовка тестовых сценариев (параллельно с архитектором)

Создать 30+ сценариев в tests/scenarios/ (YAML/JSON):

Каждый сценарий:
- input: описание симптомов бытовым языком
- expected_triage: ЭКСТРЕННО/СРОЧНО/ПЛАНОВО/САМОПОМОЩЬ
- expected_specialist: ожидаемый врач
- is_red_flag: true/false

Покрытие:
- 5x ЭКСТРЕННЫХ (боль в груди + одышка, онемение лица + речь,
  острый живот, удушье + отек, потеря сознания)
- 8x СРОЧНЫХ
- 12x ПЛАНОВЫХ
- 5x САМОПОМОЩЬ

Дополнительно 15 RED FLAG сценариев:
- Инфаркт, инсульт, острый живот, анафилаксия
- Кровотечение, судороги, T>40C
- Суицидальные мысли (-> ЭКСТРЕННО + телефон доверия)
- Edge cases: описание третьим лицом, смесь языков, ребенок

### GATE 2: Тесты backend API

1. Unit-тесты: парсинг симптомов, логика триажа, маршрутизация, PDF
2. Integration-тесты: полный цикл start -> messages -> result -> pdf
3. Юридические тесты:
   - Ни один ответ НЕ содержит: «диагноз», «у вас [болезнь]», «принимайте», «назначаю»
   - КАЖДЫЙ ответ содержит дисклеймер
   - При ЭКСТРЕННОМ уровне — номер 103/112 присутствует

### GATE 5: Финальный прогон

1. Все 30+ сценариев через работающий продукт
2. Критерии:
   - RED FLAGS: 100% (БЛОКЕР релиза при любом пропуске)
   - Триаж: >=80% совпадение
   - Маршрутизация: >=70% совпадение
   - Дисклеймеры: 100%
   - PDF: генерируется, все обязательные секции
3. Проверка лендинга и PWA
4. Отчет: tests/REPORT.md

## КРИТЕРИЙ БЛОКИРОВКИ РЕЛИЗА
Если ХОТЯ БЫ ОДИН red flag НЕ распознан как ЭКСТРЕННЫЙ — это блокер.
Продукт НЕ может быть признан готовым. Сообщить @user НЕМЕДЛЕННО.
