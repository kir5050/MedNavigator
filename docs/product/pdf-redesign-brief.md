# PDF Redesign Brief

**Статус:** согласовано, ждёт реализации после output safety  
**Дата фиксации:** 2026-05-18  
**Контекст:** замена текущего PDF («Информационная выписка») на новый формат («Маршрутный лист»). Реализация будет после закрытия задачи output safety.

---

## 1. Концепция

**Что меняем:** PDF перестаёт быть медицинской выпиской и становится routing summary — маршрутным листом для подготовки к визиту.

**Аудитория:** один документ для пациента, который тот при желании может показать врачу. Не два отдельных view, не doctor-mode как фича.

**Регуляторная рамка:** документ остаётся в категории «информационная услуга», а не «медицинский совет». Никаких диагнозов, медицинских терминов, направленной дифференциальной диагностики.

---

## 2. Что переименовываем

| Было | Стало |
|---|---|
| MedNavigator — Информационная выписка | MedNavigator — маршрутный лист |
| Информационная выписка | Маршрутный лист |
| Описание для врача | Что вы описали |
| По данным триажа | (удалено) |
| Цефалгия / артралгия / прочие медицинские термины | Слова пациента |

**Запрещённые слова в user-facing контенте PDF:**
- триаж, триажа, по данным триажа
- цефалгия, артралгия и прочие медицинские термины из МКБ
- медицинская выписка, заключение, предварительный диагноз

## 3. Финальная структура PDF

### 3.1. Header

```
MedNavigator — маршрутный лист
Помогает подготовиться к визиту и выбрать следующий шаг

Дата · ID сессии
```

Компактно, бренд не доминирует.

### 3.2. Следующий шаг (главный блок)

```
Рекомендуемый следующий шаг
[Основной специалист]
Записаться [срочность]

Это подходящий первый специалист для очной оценки описанных жалоб
и решения, нужен ли другой врач.
```

**Один primary specialist**, не три равнозначных.

**Безопасные формулировки** для краткого объяснения:
- ✅ «Врач на очном приёме сможет уточнить детали жалоб и определить дальнейшие шаги»
- ❌ НЕ «чтобы связать [симптом] с возможными общими причинами»
- ❌ НЕ «может быть связано с системой нервной системы»

### 3.3. Что вы описали

```
Что вы описали
— [жалоба простыми словами пациента]
— [жалоба простыми словами пациента]
```

**Ключевой принцип:** простые слова пользователя, не медицинский перевод.

- ✅ «болит голова»
- ❌ НЕ «цефалгия без уточнения локализации»

### 3.4. Также может пригодиться

```
Также может пригодиться

В зависимости от очной оценки врач может направить к другому специалисту,
например к [специалист 1] или [специалист 2].
```

Вторичные специалисты — мягко, условно, **не как самостоятельная рекомендация от сервиса**. Не повторять подготовку для каждого.

### 3.5. Подготовка к визиту

```
Подготовка к визиту
□ вспомните, когда начались жалобы
□ отметьте, что усиливает или уменьшает симптомы
□ возьмите список лекарств, витаминов и добавок
□ возьмите прошлые анализы, снимки или выписки, если они есть
```

**Один общий чек-лист, максимум 5 пунктов.** Не персонализировать по специалистам.

### 3.6. Возможные вопросы врачу

```
Возможные вопросы врачу
1. Что может быть следующим шагом в моей ситуации?
2. Нужно ли наблюдать симптомы и на что обращать внимание?
3. Нужно ли мне обратиться к другому специалисту?
```

**Generic вопросы**, 2-3 максимум. Не назначают исследования, не подсказывают диагностику.

- ❌ НЕ «какие обследования стоит обсудить» (это medical agenda от AI)
- ❌ НЕ «какие признаки должны насторожить» (это направленная дифдиагностика)

### 3.7. Когда нужно действовать срочнее

```
Когда нужно действовать срочнее
Если состояние резко ухудшается, симптомы быстро нарастают,
появляется ощущение угрозы жизни или вы не можете дождаться планового приёма —
обратитесь за срочной медицинской помощью.
В экстренной ситуации звоните 103 или 112.
```

**Статический блок, не LLM-generated.** Generic guidance, без перечисления конкретных red-flag симптомов под текущую жалобу.

### 3.8. Disclaimer

```
Важно: MedNavigator не ставит диагноз и не назначает лечение.
Документ носит справочный характер и помогает подготовиться к обращению к врачу.
```

Компактно, 2 строки. Не огромный юридический абзац.

## 4. Правила контента (жёсткие лимиты)

| Элемент | Лимит |
|---|---|
| Основной специалист | 1 |
| Дополнительные специалисты | максимум 2 |
| Подготовка к визиту | максимум 5 пунктов |
| Вопросы врачу | максимум 3 |
| Главный вывод (текст под специалистом) | до 280 символов |
| Краткое объяснение маршрута | до 350 символов |

**Дополнительные правила:**
- Не повторять одинаковые пункты подготовки у разных специалистов
- Симптомы дедуплицировать: показывать только нормализованные, синонимы не выводить в PDF
- Ход опроса в основной PDF **не включается**

## 5. Архитектура: PDF View Model

PDF должен строиться не из сырого `data`, а из специально подготовленного view model:

```python
pdf_view_model = {
    "title": "Маршрутный лист для визита к врачу",
    "urgency": {
        "level": "medium",
        "label": "Записаться в ближайшие 1–2 дня",
    },
    "primary_route": {
        "specialty": "Терапевт",
        "reason_short": "...",
        "timeframe": "1–2 дня",
    },
    "secondary_routes": [
        {"specialty": "Невролог", "condition": "..."},
        {"specialty": "Ортопед", "condition": "..."},
    ],
    "what_patient_described": ["болит голова", "ломит колено"],
    "preparation_checklist": [...],  # одно общее, не per-specialty
    "questions_for_doctor": [...],  # 2-3 generic
    "urgent_care_block": "<static text, not LLM-generated>",
    "disclaimer": "<compact, 2 lines>",
}
```

Это позволит контролировать длину, порядок, приоритеты, и накладывать output safety фильтр на финальный текст.

## 6. Техническая верстка

- Footer перенести в `@page @bottom-left` / `@bottom-right`, не держать как отдельный `<div>`
- Disclaimer компактный + `page-break-inside: avoid`
- Карточка primary specialist — крупная; secondary — компактные строки
- Цель: 1 страница для обычной ситуации, 2 если есть документы / сложная история / crisis

---

## 7. Что убираем из текущего PDF

- Секцию «Описание для врача» (полностью)
- Слово «триаж» и производные (везде в user-facing PDF)
- «Ход опроса» в основной PDF (можно опционально в приложении, но по умолчанию нет)
- Перечисление конкретных red-flag симптомов в PDF
- Дублирующиеся подготовки для каждого специалиста
- Длинный disclaimer
- Медицинские термины («цефалгия» и подобные)
- Каузальные формулировки («может быть связано с системой...»)

---

## 8. Crisis-сессии — без изменений

PR #11 уже обеспечивает корректное поведение для crisis-only сессий: crisis-баннер сверху, скрытие routine-секций. Эта логика **остаётся как есть**, новая структура PDF применяется к **non-crisis** сессиям.

---

## 9. Связь с output safety

После реализации output safety (regex/keyword фильтр на финальном тексте LLM) — этот фильтр будет применяться к LLM-генерируемым полям view model'а: `primary_route.reason_short`, `what_patient_described` (если LLM-обогащённое), `secondary_routes[].condition` (если LLM-обогащённое).

Статические блоки (`urgent_care_block`, `disclaimer`, header, заголовки секций) — output safety не нужен, они хардкод.
